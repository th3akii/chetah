# Typed models from a schema file — how everything works

> Status: initial draft · applies to Milestone 002 (schema-first typed models)

This document explains the complete milestone-002 flow: one JSON schema file is
the single source of truth that produces C# models **and** table metadata, a CLI
generator emits one deterministic source file, and the existing Postgres
executor returns strongly typed records.

```
myorm-schema.json → MyOrm.CodeGen → MyOrm.Schema.g.cs → db.QueryAsync(...) → List<User>
```

See [`BASIC_SELECT.md`](BASIC_SELECT.md) for the underlying describe → compile →
execute → map layering; nothing below changes those boundaries.

## Step 1 — the schema file

The schema is JSON, parsed with `System.Text.Json` (no custom parser). Example
([`examples/BasicExample/myorm-schema.json`](../examples/BasicExample/myorm-schema.json)):

```json
{
  "tables": [
    {
      "name": "users",
      "model": "User",
      "columns": [
        { "name": "id", "type": "integer", "nullable": false },
        { "name": "name", "type": "text", "nullable": false },
        { "name": "age", "type": "integer" }
      ]
    }
  ]
}
```

Rules:

- `name` — the real PostgreSQL table name (stored raw; the dialect compiler
  quotes it at SQL generation time, exactly as in milestone 001). Letters,
  digits, underscores and hyphens are supported; names that cannot produce a
  valid C# accessor class (everything else, e.g. spaces or quotes) are
  rejected with that reason in the error.
- `model` — optional C# model name. Default: PascalCase of the table name.
  Model and accessor names must be unique across the whole schema.
- `columns[].type` — one of `integer`, `bigint`, `text`, `boolean`, `uuid`,
  `timestamp`. Anything else is rejected with the supported list in the error.
- `columns[].nullable` — optional. **Omitted means nullable**, matching
  PostgreSQL's own default. `"nullable": false` marks a NOT NULL column.
- Column names must be plain identifiers (`[A-Za-z_][A-Za-z0-9_]*`) because they
  become C# property names (`first_name` → `FirstName`) and database rows are
  read by name. PostgreSQL columns that require quoting (spaces, `@`…) are
  rejected rather than half-supported.
- Validation errors: empty/duplicate names, unsupported types, invalid or
  clashing C# names, columns whose PascalCase forms collide (`user_id` and
  `user__id` both map to `UserId`), zero columns/tables. The parser never
  partially emits code.

## Step 2 — run the generator

```sh
dotnet run --project src/MyOrm.CodeGen -- --schema <schema.json> [--out <dir>] [--namespace <ns>]
```

- `--out` (default `.`): directory that receives **`MyOrm.Schema.g.cs`**.
- `--namespace` (default `MyOrm.Generated`): namespace of generated code.

Guarantees:

- Output is deterministic — same schema, same bytes (a test pins the checked-in
  file to a fresh render so the two can never drift apart).
- Only that one file is written; it is clearly marked `<auto-generated>` and
  starts with `#nullable enable`. Your other sources are never touched.

## Step 3 — what gets generated

One accessor class and one record per table
([full example](../examples/BasicExample/Generated/MyOrm.Schema.g.cs)):

```csharp
public static class UsersTable
{
    // Typed column metadata — the basis for future Where/Select chains.
    public static readonly MyOrm.Column<int> Id = new("id");
    public static readonly MyOrm.Column<int?> Age = new("age");

    // Table metadata handed to the existing query objects. Built from the
    // typed columns, so schema information is not duplicated inside the file.
    public static readonly MyOrm.Table Table = new("users", Id.Name, Name.Name, Age.Name);

    // Hand-coded (generated) row mapper — no reflection.
    public static User Map(NpgsqlDataReader reader)
    {
        var ageOrdinal = reader.GetOrdinal("age");
        return new User(
            reader.GetInt32(reader.GetOrdinal("id")),
            reader.GetString(reader.GetOrdinal("name")),
            reader.IsDBNull(ageOrdinal) ? null : reader.GetInt32(ageOrdinal)
        );
    }
}

public sealed record User(int Id, string Name, int? Age);
```

Naming: accessor class = PascalCase(table name) + `"Table"` (`users` →
`UsersTable`); record = `model` or PascalCase(table name) (`User`).
Non-nullable columns keep their bare CLR type (`int`, `string`); nullable
columns become `int?` / `string?`.

Type map: `integer`→`int`, `bigint`→`long`, `text`→`string`,
`boolean`→`bool`, `uuid`→`Guid`, `timestamp`→`DateTime`.

## Step 4 — typed SELECT

The generated metadata feeds the untouched milestone-001 pipeline:

```csharp
var db = new PostgresDb(connectionString);
var users = await db.QueryAsync(UsersTable.Table.SelectAll(), UsersTable.Map);
foreach (var user in users)
    Console.WriteLine($"{user.Id} {user.Name} ({user.Age})"); // IntelliSense on all three
```

- SQL identifiers come only from `UsersTable.Table` metadata; quoting remains
  the compiler's job. No user string ever reaches the SQL text.
- Mapping is the generated `Map` function: one `GetOrdinal` per nullable
  column, typed reader calls, explicit `IsDBNull` handling. Hand-written per
  row in the generator rather than reflective, so it is debuggable and free of
  per-row reflection cost.
- The database-centric `db.Select<User>()` API from
  [`DECISIONS.md`](DECISIONS.md) D001 remains the target; it will compose on
  top of exactly these generated pieces.

## Tests

`tests/MyOrm.CodeGen.Tests`:

- **Schema parsing/validation** — valid parse, defaults, unsupported types,
  duplicate/invalid names, empty tables/columns.
- **Code generation** — determinism, rendered types/nullability, nullable
  reader branches, and a pinning test: the checked-in generated file must equal
  a fresh render from `schema.json`.
- **Type mapping** — every PostgreSQL type name → CLR type.
- **Typed SELECT** — live-database round trip (same `MYORM_CONNECTION_STRING`
  variable) creating/dropping only `test_widgets`, asserting typed records and
  `NULL` mapping.

Backward compatibility of milestone 001 is covered by the unchanged
`tests/MyOrm.Core.Tests` and `tests/MyOrm.Postgres.Tests`.

## Deliberate limits

Not implemented, not hidden: `WHERE`/`JOIN`/`ORDER BY`/`LIMIT`, writes,
migrations, schema introspection, SQL Server, Roslyn source generators,
relationships. `timestamp with time zone` and other PostgreSQL types are not in
the type map yet. Mapping trusts the schema's nullability claim — a DB that
returns `NULL` for a `"nullable": false` column will surface as a runtime
error from the reader, not silent mis-mapping.
